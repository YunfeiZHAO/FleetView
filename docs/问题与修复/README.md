# 问题与修复

FleetView 在实际使用中出过的问题，每个问题一份记录：现象、怎么查到的、根因、修了什么、怎么验证、还有什么没覆盖。

和 `docs/design/` 的分工：`design/` 放实现之前写的设计文档；这里放出了事之后的记录。一次事故如果引出了较大的设计改动，设计文档仍放 `design/`，两边互相链接。

## 命名约定

```
YYYY-MM-DD-<问题简述>.md
```

日期是发现问题的日期。文档写完不删、不覆盖；同一问题又出现时，在原文档末尾追加一节，标明日期。

## 文档头

每份文档开头放一个元信息表：

| 字段 | 说明 |
|---|---|
| 发现日期 | `YYYY-MM-DD` |
| 状态 | 排查中 / 已修复（未部署）/ 已修复 / 已知未修 |
| 影响 | 一句话：谁、损失了什么 |
| 对应代码版本 | 写作时的 git commit |
| 修复 | 修改了哪些文件；有 commit 就写 commit |
